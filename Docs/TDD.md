## 2. 화면과 기능

* **화면**: 보드는 uGUI(Screen Space - Overlay, 2026-09-28 사용자 결정 — 렌더 스케일 0.8의 영향을 받지 않고 입력이 UI와 한 체계). 화면 흐름 = `GameFlow`(Phase 4.3): 씬 하나에서 타이틀(`TitleScreen`, Phase 7.3 — 주소에 `?stage=`가 있으면 건너뜀) · 선택 화면(`StageSelectView`) · 보드(`BoardScreen` — `PuzzleController.Open`으로 스테이지를 바꿔 연다) · 옵션(`OptionsView`) · 기록(`StatsView`) 패널을 켜고 끈다(씬 다시 불러오기 없음). 화면 · 패널은 켜질 때 0.2초 동안 나타난다(`ScreenFade` — 투명도만, 입력은 막지 않음). 저장소 · `SaveData`(진행 · 기록 · 설정) · 광고 자리는 `GameFlow`가 한 번 만들어 넘긴다.
* **선택 화면 버튼**(2026-11-23 사용자 — A+B): 스테이지 버튼은 `HoneycombLayout`으로 4 · 3줄을 번갈아 맞물린 벌집(칸은 정육각형을 담는 정사각형 259 — 이웃 칸과 겹치므로 `StageButtonView`가 `ICanvasRaycastFilter`로 육각형 안쪽만 누른 것으로 본다). 깬 판은 그 판 대표 색(`Stage.MainTargetColor` — 목표에서 칸이 가장 많은 색, 같으면 작은 색 값)을 그 판 팔레트로(`PuzzleController.StageColor`, 주소 `?palette=` 우선) 채우고, 번호는 크림색 + 진갈색 외곽선(테두리 글자 — 2026-11-23 사용자: 목록 제목 줄 · 육각 번호는 크림색, 클리어 띠 문구는 노랑, 타이틀 "컬러링붓"은 글자마다 기본 팔레트 빨강 · 노랑 · 파랑 · 초록(리치 텍스트 `<color>`). 재질 `Dongle SDF Outline.mat`은 `BuildScene`이 폰트 재질로 만든다 — 폰트를 다시 만들면 `BuildScene`도), 완벽 별은 진갈색 별 위 노란 별.
* **여러 챕터**(2026-10-11 사용자 결정): 목록 화면의 작은 그림 양옆 ◀ ▶로 챕터를 넘긴다(`StageSelectView.ChapterStepped` — 넘길 챕터가 없으면 숨김). 잠긴 챕터는 제목 "챕터 N · 잠김" · 버튼 모두 잠김 · 누르면 "앞 챕터 그림을 완성하면 열려요"(해금은 Core `Progress.IsChapterUnlocked`). 그림을 완성하면 그림 화면 버튼이 [다음 챕터] → 다음 챕터 목록. 타이틀 [시작]은 아직 완성하지 않은 첫 챕터(`Progress.CurrentChapter`). 챕터 2 "봄 정원"(스테이지 11개 `Garden…` · 팔레트 정원 · 봄볕)을 2026-11-15에, 챕터 3 "여름 바닷가"(스테이지 11개 `Beach…` · 팔레트 바닷가 · 물가)를 2026-11-16에, 챕터 4 "가을 숲길"(스테이지 11개 `Autumn…` · 팔레트 단풍 · 노을)과 챕터 5 "눈 내린 밤"(스테이지 11개 `Winter…` · 팔레트 밤 · 눈마을 — 완성하면 [목록])을 같은 날 등록했다(계획 `Docs/plans/2026-11-14-chapters-2-5.md` — 게임이 여는 챕터는 `BoardSceneBuilder.Chapters`, 임시 챕터 2 · 주소 `?chapters`는 같은 날 뺌). 테스트 주소의 `?unlock`은 모든 챕터 · 스테이지를 연다(`GameFlow._unlockAll` — 표시 · 판정만 바꾸고 해금 상태는 저장하지 않음. 그 상태로 깬 클리어 기록은 평소처럼 남는다).
* **따라 하기 · 힌트**(2026-10-07, GDD §6): 따라 하기 = 처음 [시작] 때(봤는지는 `SaveData.TutorialSeen`) · 옵션 "규칙 다시 보기" → `PuzzleController.OpenLesson` — 레슨 i = `TutorialCatalog`의 i번째 스테이지 + `TutorialLessons`(그을 획 · 한 줄 문구, 손가락이 가리킨 칸 · 방향만 받음(2026-11-13 — 전에는 같은 줄이면 어느 칸이든. 다른 칸에서 시작하면 "손가락이 있는 칸에서 끌어 주세요", PC 숫자키는 선택이 없으면 손가락 칸부터) — 마지막 복습은 혼자 풀기: 아무 획 · 힌트 사용 가능). 힌트 = Core `PuzzleSession.StartHint` → `HintSearch.Step`(다음 한 수 · 몇 수 되돌릴지, 탐색 상한은 상태 하나당 `HintSearch.RuntimeLimit` 20만 — 한 번에 끝까지 도는 `FindHint`는 도구 · 테스트용). `PuzzleController`가 프레임마다 `HintFrameMs`(40 ms — PC Chrome 호박 막다른 길: 프레임 간격 최대 51 ms · 누른 뒤 결과까지 약 1.2초, `DECISIONS.md` 2026-11-17)씩 나눠 돌린다(2026-11-17 — 한 번에 돌면 PC WebGL에서 1.3초 멈췄다): 첫 프레임 몫 안에 끝나면 바로 결과, 아니면 안내 띠 "힌트를 찾고 있어요"를 띄우고 코루틴으로 이어 돈다. 힌트 횟수(`Stats.Hinted`)는 누를 때 센다. 보드를 떠나거나 다른 판을 열면(`Close` · `Open`) 탐색을 버린다 — `PuzzleController`는 씬 루트에 있어 보드 화면이 꺼져도 코루틴이 저절로 멈추지 않으므로 직접 멈춘다. 결과 → `BoardView.ShowGuide`(손가락 표시 + 미리보기 — 손가락은 사용자 그림 스프라이트 `Finger`, 손끝 pivot을 칸 가운데에 두고 끄는 방향으로 움직였다 흐려짐, 2026-11-13) · 안내 띠, 보상형 광고 자리(`IAdService.ShowRewarded`)를 거친다. "완벽"은 힌트와 무관.
* **스케치북**(2026-10-07, GDD §5): 타이틀 · 목록 아래 [스케치북](따라 하기 뒤) → `EndlessView`(난이도) → `GameFlow.OpenEndless` — 퍼즐 i = 묶음의 i번째 줄, 기록 키 `Endless{난이도}{번호}`(퍼즐마다), 진행은 Core `EndlessProgress`(지금 번호 · 푼 수 · 건너뛴 수). 풀린 판을 떠날 때 다음 번호로. 위 가운데 [건너뛰기](안 풀린 판은 힌트처럼 보상형 광고 자리 `IAdService.ShowRewarded`를 거침, 2026-10-17 — 지나간 판은 다시 하지 않음: 묶음을 다 돌면 처음부터). 그림 보상 없음.
* **보드 연출**(Phase 7.4) = `BoardView.PlayStroke` · `PlayClear` · `PlayShake`(값은 `MotionSettings`) — 세션 상태는 즉시 바뀌고 화면만 늦게 따라간다(경로는 Core `Trace`). `Render`가 진행 중인 연출을 끝난 모습으로 정리한다.
* **입력 잠금**(2026-10-08 · 10-05): `PuzzleController`는 클리어 또는 막힘이면 보드 입력(끌기 · 탭 · 방향 버튼 · 키보드)을 받지 않는다 — 되돌리기 · 처음부터 · 막힘 띠 되돌리기 · 힌트는 그대로. 보드를 덮는 패널(`_overlays` — 옵션 · 기록)이 열려 있으면 키보드를 무시하고, 되돌리기 · 처음부터는 끄는 중인 획을 취소한다(`BoardView.CancelDrag`). 힌트 탐색이 여러 프레임에 걸치는 동안(2026-11-17)은 보드 입력 · 되돌리기 · 처음부터 · 힌트를 모두 받지 않는다 — 잠금 상태는 `Refresh` 한 곳이 정하고(탐색 중인지 `_hintSearch`를 본다 — 버튼 흐림 · 보드 입력 · 이전 힌트의 손가락 표시 끄기), `Undo` · `Restart` · `RequestHint` · `OnBrushRequested` 안에서도 막는다(Ctrl+Z는 `Undo`를 바로 부른다). 탐색이 끝나면 잠금을 그냥 풀지 않고 `Refresh`로 지금 상태에 맞춘다(막힌 판의 보드 입력은 잠긴 채). 탐색이 예외로 끝나면 탐색을 버리고 `Refresh` → "힌트를 찾지 못했어요" → 예외는 그대로 던진다(잠금이 남지 않게).
* **챕터 그림**(Phase 5) = `ChapterArt`(선화 + 단계 조각, 단계 i ↔ 목록의 i번째 스테이지) · `ChapterView`(선택 화면 위 작은 그림 · `ChapterScreen` 큰 그림): 처음 클리어하면 클리어 띠가 뜰 때(`PuzzleController.ClearShown`) 그림 카드(`ClearBanner/PaintCard` — 그림 · 진행 문구 "챕터 부제 n / m"(예: "포도밭 오후 4 / 11" — 2026-11-20 사용자, 옛 "색칠 n / m"), 보이는 동안 `GameFlow.LateUpdate`가 매 프레임 보드 영역 가운데에 맞춤 — 회전 · 창 크기 · 되돌린 뒤 다시 풀기 모두)에서 그 단계를 확대해 칠한 뒤 전체로 물러나고(칠하기는 붓질 — 셰이더 `ColoringBoot/UI/BrushReveal`(`Assets/Art/Shaders/`)을 칠하는 1초 동안만 그 조각에 걸어 위에서부터 2~5줄(조각 세로/가로 비율 × 3)을 왼→오 · 오→왼 번갈아 드러냄, 끝은 붓털처럼 울퉁불퉁 — 2026-11-24. 셰이더는 `ChapterView._brushShader` 참조로 빌드에 들어감 · `ChapterView._focusZoom` — 카드 그림만. `ChapterView`는 `Picture/Clip/Content`(바탕 · 단계 · 선화) + `Picture/Frame`(테두리)로 그리고, 확대는 `Content`만 · 확대를 쓰면 `Clip`에 RectMask2D — 테두리는 확대되지도 잘리지도 않음), 띠 "다음"은 바로 다음 스테이지로 간다(B안 채택, 2026-11-13 사용자 — `DECISIONS.md`). 챕터를 완성한 클리어만 카드 없이 "다음" → 그림 화면(`ChapterScreen`) — 완성 문구는 챕터 부제(예: "포도밭 오후", 부제가 비면 "그림 완성!" — 2026-11-20 사용자). 띠가 뜨기 전에 목록 버튼으로 나가면 목록의 작은 그림에서 칠한다. 다시 클리어하면 칠하지 않는다(`PuzzleController.FirstClear`). 카드는 띠의 자식이라 띠와 함께 켜지고 꺼지며, 스테이지 · 레슨 · 스케치북를 열 때 `GameFlow`가 끈다. 그림을 바꿀 땐 (완성 그림 한 장이면 `ArtSplit.py` →) `ChapterArtExport.py` → `ChapterArtBuilder`를 차례로 실행한다(`AgentScripts/README.md`). 단계 조각 파일 이름이 같으면 `.meta` GUID가 유지되고 `ChapterArt`의 조각 위치만 바뀐다 — 첫 클리어 카드의 확대 배율은 조각 크기에서 나오므로 그림을 바꾸면 달라진다.

## 4. 스테이지 데이터 · 저장 형식

* 프로토타입 포맷 `{"name": ..., "cells": [[q, r, 시작 색, 목표 색], ...]}` (GDD §3) + 선택 필드 `palette`(팔레트 이름, 없으면 기본 팔레트) · `minMoves`(최소 수, 솔버가 채움, 없으면 미표시). 로직은 `palette`를 이름(문자열)으로만 들고, 팔레트 에셋을 고르는 일은 표현 계층이 한다. 프로토타입에 들어 있는 스테이지 9개(포도 포함)는 이 포맷 그대로 옮겨 쓸 수 있다. 읽기는 `Stage.Parse` — Core 전용 파서다(`JsonUtility`는 UnityEngine이고 중첩 배열을 못 읽음, 2026-09-28 사용자 결정). `name` · `cells` 필수, 모르는 키 · 0~7 밖의 색 · 좌표 중복은 `FormatException`.
* **저장 형식 (2026-09-29 사용자 결정)**: 스테이지 = `Assets/Data/Chapters/ChapterN/Stages/<영문 이름>.json` TextAsset(이 포맷 그대로 — 프로토타입 코드와 복사 · 붙여넣기로 오감, git 차이가 읽힘). `minMoves`는 레벨 에디터가 저장할 때 솔버로 채운다. 순서 민감도는 저장하지 않고 에디터에만 표시. 게임이 여는 스테이지 목록은 `StageCatalog`(ScriptableObject, JSON TextAsset 순서 목록 — Phase 4 스테이지 선택 화면도 이것을 쓴다). 챕터는 `Chapter` 에셋(제목 · 부제 · 목록 · 그림, 2026-10-07)이 묶고 `GameFlow._chapters`(차례 — 앞 챕터 그림을 완성하면 다음 챕터, 2026-10-11)가 연다 — 파일 이름은 진행 기록의 키라 챕터 · 따라 하기 · 시험 목록 모두에서 겹치면 안 된다(`ContentRegressionTests`).
* **출시 뒤 스테이지 교체 (2026-11-18)**: 진행 · 플레이 기록은 파일 이름으로 판을 가리킨다. 출시한 판의 내용(칸 · 목표)을 바꿀 때는 **새 파일 이름**으로 넣고 목록의 옛 파일을 뺀다 — 같은 이름에 다른 판을 넣으면 옛 판의 클리어 · 최고 수가 새 판에 그대로 붙는다. 새 이름으로 바꾸면 그 판은 다시 안 깬 상태가 되고 뒤 판이 잠길 수 있으니(차례 해금), 교체 범위와 함께 이 영향을 정한다. 도구 주의: `Phase8Chapters.AddStage`는 같은 이름을 물어보지 않고 덮어쓴다(`AgentScripts/README.md`). 출시 전(지금)은 이름을 그대로 두고 내용만 바꿔도 된다(정식 테스트 전 — 사용자, 2026-10-10).

## 5. 저장 · 플랫폼 서비스

* 저장은 `PlayerPrefs`를 직접 부르지 않고 인터페이스 뒤에 둔다(앱인토스에서 네이티브 저장소로 교체). 광고는 인터페이스 자리만. 사운드 켜고 끄기와 백그라운드 전환 시 정지는 처음부터 구조에 넣는다. 효과음은 `SoundController`(클립 · 버튼 OnClick 배선은 `BoardSceneBuilder`, 획 소리 규칙은 `DECISIONS.md` 2026-11-08). 구현(2026-09-30): `IKeyValueStore` · `PlayerPrefsStore`(쓸 때마다 `PlayerPrefs.Save()` — WebGL은 그래야 IndexedDB에 남음), 키 `ColoringBoot.Progress`(클리어 · 최고 기록, Core `Progress`) · `ColoringBoot.PlayStats`(플레이테스트 기록, Core `PlayStats`) — 저장 형식은 머리줄(`progress 1` · `stats 2` — 2026-10-07 힌트 칸, `stats 1`도 읽음) + 탭 구분 줄, 깨지면 읽은 만큼으로 시작하고 버린 것을 드러낸다(아래 "읽지 못한 저장 값"). 따라 하기를 봤는지는 `ColoringBoot.Tutorial`, 스케치북 진행은 `ColoringBoot.Endless`(`endless 1`, 2026-10-07) — `?reset`이면 함께 지움. 스테이지는 파일 이름으로 구분. 광고는 `IAdService` · `NoAdService`. 주소 쿼리(테스트 주소 — GitHub Pages · localhost · 127.0.0.1 — 에서만, `UrlQuery.IsQaHost`, 2026-10-07): `?stage=<파일 이름>` · `?stats`(기록 패널 — 모든 챕터 + 따라 하기 + 스케치북, `?lab`과 함께면 시험 목록도 — 2026-11-15) · `?reset`(진행 · 기록 지우기) · `?palette=<이름>`(모든 스테이지를 그 팔레트로 — 색 확인용) · `?lab`(시험 목록 11개 — 소재 맵 시험 · 챕터 1에서 빠진 옛 판, 모두 열림 · 그림 화면 없음, 2026-10-06 · 10-11 · 기믹 판은 10-12에 뺌) · `?unlock`(모든 챕터 · 스테이지 열기 — 해금 상태는 저장하지 않음, 2026-11-15. 옛 `?chapters` 임시 챕터는 같은 날 뺌).
* **읽지 못한 저장 값**(2026-11-19, `DECISIONS.md`): Core `Progress` · `PlayStats` · `EndlessProgress`의 `Deserialize(text, out RecordReadStatus)`가 읽은 기록과 함께 상태를 돌려준다 — `Ok`(값 없음 · 공백뿐인 값 포함) · `LinesDropped`(머리줄은 맞고 읽을 수 없는 줄을 건너뜀 — 공백뿐인 줄 · 같은 이름의 줄은 세지 않음) · `NewerVersion`(머리줄 이름이 같고 번호가 정수로 더 큼 — 예 `progress 2`) · `Unreadable`(그 밖). 읽는 기록 · 건너뛰는 줄은 전과 같다. 공백 값 · 머리줄 판정 · 빈 줄 건너뛰기 · 버린 줄 표시는 `RecordHeader.Read` 한 곳(각 기록은 줄 하나 읽기만 넘김). 상태를 버리는 단일 인자 `Deserialize`는 두지 않는다(읽기 실패가 다시 묻히지 않게). `SaveData`는 `Ok`가 아니면 키마다 `[저장]` 경고를 1회 남긴다(백업과 같은 원본이면 — 저장이 없어 지난 실행의 깨진 값이 남음 — 경고 대신 일반 로그). `LinesDropped` · `Unreadable`(다음 저장이 원본을 덮는 경우): 원본을 `<키>.Unread`(`ColoringBoot.Progress.Unread` · `ColoringBoot.PlayStats.Unread` · `ColoringBoot.Endless.Unread`)에 복사(이미 있으면 이번 원본으로 바꿈 — 진행이 가장 많이 남은 최근 원본을 지킨다, `DECISIONS.md` 2026-11-19 코드 리뷰 후속)한 뒤 지금처럼 저장. `NewerVersion`(캐시된 옛 빌드가 새 빌드의 값을 읽음): 백업 없이 이번 실행 동안 그 키에 쓰지 않는다 — 원본이 그대로 남고, 그 실행의 그 기록은 메모리에만(막힌 저장마다 로그를 더 남기지 않음). `?reset`은 `GameFlow.Awake`가 `SaveData`를 만들기 **전에** `SaveData.ClearRecords(store)`로 기록 · 백업 키 셋 · 따라 하기 기록을 지운다 — 곧 지울 값에 경고 · 백업이 생기지 않고, 새 버전 값이었던 키도 그 실행에서 정상 저장. 화면 안내는 없다(로그만). 테스트: 세 기록 테스트의 `*_Status_*` · `SaveDataTests`(메모리 저장소).
* **안전영역**(2026-11-11): 모든 화면 · 패널은 `Canvas/SafeArea` 아래에 있고, `SafeAreaFitter`가 화면 크기 · `Screen.safeArea`가 바뀌거나(매 프레임 확인) WebGL에서 토스 인셋 번호가 바뀌거나 지난 토스 값 읽기가 실패했을 때(0.5초마다 확인) 이 패널의 앵커를 맞춘다. WebGL 빌드(`#if UNITY_WEBGL && !UNITY_EDITOR`)만 자체 jslib `Assets/Plugins/WebGL/ColoringBootSafeArea.jslib`으로 앱인토스 `window.AppsInToss.SafeAreaInsets.get()`(CSS px)과 캔버스 CSS 크기(`Module.canvas`)를 읽어 `Screen.safeArea`와 겹치는 영역(축마다 더 안쪽)을 쓴다 — 위는 `top + 10 + 44 + 8`(토스 `⋯ ✕`의 공식 위치 Android 10 · 높이는 공식 값이 없어 캡처 추정 약 34에 여유), 아래 · 왼쪽 · 오른쪽은 인셋 그대로(기기 노치 · 홈 표시줄의 `Screen.safeArea`가 더 안쪽이면 그쪽 — 2026-11-11 리뷰: Android 토스 인셋은 아래 0). 인셋과 캔버스 크기가 모두 CSS px라 배율을 쓰지 않는다(전제: 캔버스가 뷰포트를 덮음 — `AITTemplate`, 실기 확인). jslib은 브리지가 처음 보일 때 · 변경 구독이 성공할 때 · SDK `SafeAreaInsets.subscribe`의 `onEvent`마다 번호를 올리고(`CbSafeAreaVersion` — 구독이 실패했으면 부를 때마다 다시 시도), `SafeAreaFitter`는 0.5초마다 그 번호를 보고(토스 밖 WebGL의 JS 호출을 줄임) 번호 · 화면 크기 · `Screen.safeArea` 중 하나가 바뀌거나 지난 읽기가 실패했으면 `CbSafeAreaRead`로 여섯 값을 한 번에 읽는다(여섯 값을 모두 검사한 뒤에만 씀)(2026-11-11 보강 — 브리지가 늦게 생기거나 인셋만 바뀌어도 다시 맞춤). 토스 값을 못 쓰면 `Screen.safeArea` 배치 그대로 두고 종류별로 로드당 1회 로그 — `window.AppsInToss`가 없으면 정보(토스 밖 · Pages), 있는데 못 읽으면 에러(0.5초마다 다시 읽음), 구독이 아직 안 됐으면 경고(값은 적용 · 구독은 다시 시도), 여백을 뺀 패널이 캔버스의 절반보다 작으면 경고. SDK C# API는 쓰지 않는다(`DECISIONS.md` 2026-11-11). ## 6. WebGL 설정

* WebGL Build Support 설치 · 활성 빌드 타깃 WebGL 확인(`list_build_targets` · `get_build_settings`). WebGL은 품질 레벨 `Mobile`(→ `Mobile_RPAsset`, URP)을 쓴다. 적용된 설정: 압축 Brotli + Decompression Fallback · Managed Stripping High · IL2CPP OptimizeSize · 기본 캔버스 540×960 · 데이터 캐싱 · 스레드 끔 · 스플래시 끔(Phase 4.1) · 전용 템플릿 `PROJECT:ColoringBoot` · 제품 이름 "컬러링붓" · Name Files As Hashes(Phase 7.6, `AgentScripts/Setup/Phase7WebTemplate.cs`). 텍스처 압축: 챕터 그림만 ASTC(선화 4×4 · 색칠 단계 6×6, `ChapterArtBuilder`), UI 스프라이트는 압축하지 않음(2026-10-11 사용자 결정 — 휴대폰이 그대로 써 메모리가 줄고, PC 브라우저는 불러올 때 푼다).
* 설정 이유: GitHub Pages는 `Content-Encoding: br` 헤더를 주지 못해 Brotli 파일이 그대로는 로드에 실패한다 → Decompression Fallback. 빌드 파일 이름이 매번 같으면 브라우저가 GitHub Pages 캐시(10분)의 옛 파일과 새 파일을 섞어 `RangeError: Maximum call stack size exceeded`로 멈춘다(2026-10-03) → Name Files As Hashes · 템플릿 CSS는 `index.html` 안에.
* WebGL 전용 코드는 안전영역 하나(§5 — `SafeAreaFitter`의 `#if UNITY_WEBGL && !UNITY_EDITOR` · jslib 1개). Android APK와 에디터에는 들어가지 않는다.
* 빌드 크기 · 첫 로딩 · 배포 이력은 `Docs/BuildHistory.md`.

## 8. Android 설정

* **빌드**(2026-11-10): 활성 타깃을 오간다 — `switch_build_target` Android → `unity command build --target Android --outputPath Builds/Android/ColoringBoot.apk --confirm true` → 끝나면 WebGL로 되돌린다. 빌드 프로필 없음. 시험 APK는 Unity 디버그 키, 출시 키는 `Docs/Task.md` 9.3. 전환 중에는 `AIT` 메뉴 빌드를 쓰지 않는다(SDK 전환 대화상자가 에디터를 멈춘다).
* **설정**: 패키지 `com.jhseawater.coloringboot`(Android만) · 회사 `JHSeawater` · 세로 고정(회사 · 방향은 WebGL과 공용, `AgentScripts/Setup/Phase9AndroidSettings.cs`) · IL2CPP · ARM64만 · 최소 API 26 · 타깃 API 자동(실측 36) · GameActivity · 전체 화면(탐색 바가 게임 중 가려짐) · `enableOnBackInvokedCallback=true`. 챕터 그림은 WebGL과 같은 ASTC(선화 4×4 · 색칠 6×6, `ChapterArtBuilder`).
* **코드 분기는 두 곳뿐**(`GameFlow`의 `#if UNITY_ANDROID`): 시스템 뒤로가기(`LateUpdate`가 `Keyboard.escapeKey`를 읽어 `HandleBack` — `PuzzleController.Update`의 Esc 뒤에 돌아 옵션을 닫을 때 보드 선택이 풀리지 않는다, WebGL의 Esc에는 영향 없음)와 `Application.targetFrameRate = 60`. `HandleBack`: 옵션 닫기 → 보드(목록 버튼과 같음 — 단 따라 하기 중이면 `TutorialSeen`을 저장하지 않는다) → 그림 화면(목록) → 무한 난이도(뒤로 버튼과 같음) → 목록(타이틀) → 타이틀(앱 종료).
* **빌드 부산물 — 커밋하지 않는다**: Android 전환 · 빌드 뒤 `ProjectSettings/UnityConnectSettings.asset`의 `m_Enabled`가 1이 되고 `UniversalRenderPipelineGlobalSettings.asset`에서 항목 3줄이 빠진다 → `git checkout --`로 되돌린다(2026-11-10 — 왜 바뀌는지는 확인 못 함). `.utmp/`는 Android 빌드가 만든다.
* **측정 주의**: `Builds/Android/ColoringBoot.apk`를 지우지 않고 다시 빌드하면 Gradle 증분 패키징이 옛 항목 자리를 남겨 파일이 커진다(66.7 → 96.0 MB, 내용 합은 그대로) — 크기를 잴 때는 APK를 지우고 빌드한다. adb는 전체 경로(`.../AndroidPlayer/SDK/platform-tools/adb.exe`)로, `emulator-5562` 오인식 때문에 `-s <시리얼>`을 붙인다.
* **실측 동작**: 게임 중 설정에서 탐색 바 방식을 바꾸면 Unity가 스스로 끝나고 다시 뜬다(`EXIT_SELF`, 크래시 아님). 시작할 때 `AssetPackManager` `ClassNotFoundException` 로그 한 줄이 남지만 앱은 계속 실행된다(에셋 팩을 쓰지 않음).
