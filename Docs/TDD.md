## 2. 화면과 기능

* **화면**: 보드는 uGUI(Screen Space - Overlay, 2026-09-28 사용자 결정 — 렌더 스케일 0.8의 영향을 받지 않고 입력이 UI와 한 체계). 화면 흐름 = `GameFlow`(Phase 4.3): 씬 하나에서 타이틀(`TitleScreen`, Phase 7.3 — 주소에 `?stage=`가 있으면 건너뜀) · 선택 화면(`StageSelectView`) · 보드(`BoardScreen` — `PuzzleController.Open`으로 스테이지를 바꿔 연다) · 옵션(`OptionsView`) · 기록(`StatsView`) 패널을 켜고 끈다(씬 다시 불러오기 없음). 화면 · 패널은 켜질 때 0.2초 동안 나타난다(`ScreenFade` — 투명도만, 입력은 막지 않음). 저장소 · `SaveData`(진행 · 기록 · 설정) · 광고 자리는 `GameFlow`가 한 번 만들어 넘긴다.
* **여러 챕터**(2026-10-11 사용자 결정): 목록 화면의 작은 그림 양옆 ◀ ▶로 챕터를 넘긴다(`StageSelectView.ChapterStepped` — 넘길 챕터가 없으면 숨김). 잠긴 챕터는 제목 "챕터 N · 잠김" · 버튼 모두 잠김 · 누르면 "앞 챕터 그림을 완성하면 열려요"(해금은 Core `Progress.IsChapterUnlocked`). 그림을 완성하면 그림 화면 버튼이 [다음 챕터] → 다음 챕터 목록. 타이틀 [시작]은 아직 완성하지 않은 첫 챕터(`Progress.CurrentChapter`). 지금 챕터 2는 임시(옛 판 사본 `Temp01~11` + 임시 도안, `AgentScripts/Setup/Phase8TempChapter2.cs`)이고 주소 `?chapters`일 때만 들어간다.
* **따라 하기 · 힌트**(2026-10-07, GDD §6): 따라 하기 = 처음 [시작] 때(봤는지는 `SaveData.TutorialSeen`) · 옵션 "규칙 다시 보기" → `PuzzleController.OpenLesson` — 레슨 i = `TutorialCatalog`의 i번째 스테이지 + `TutorialLessons`(그을 획 · 한 줄 문구, 정해진 줄 · 방향만 받음 — 마지막 복습은 혼자 풀기: 아무 획 · 힌트 사용 가능). 힌트 = Core `PuzzleSession.FindHint`(다음 한 수 · 몇 수 되돌릴지, 탐색 상한) → `BoardView.ShowGuide`(손가락 표시 + 미리보기) · 안내 띠, 보상형 광고 자리(`IAdService.ShowRewarded`)를 거친다. "완벽"은 힌트와 무관.
* **무한 모드**(2026-10-07, GDD §5): 타이틀 · 목록 아래 [무한 모드](따라 하기 뒤) → `EndlessView`(난이도) → `GameFlow.OpenEndless` — 퍼즐 i = 묶음의 i번째 줄, 기록 키 `Endless{난이도}{번호}`(퍼즐마다), 진행은 Core `EndlessProgress`(지금 번호 · 푼 수 · 건너뛴 수). 풀린 판을 떠날 때 다음 번호로. 위 가운데 [건너뛰기](안 풀린 판은 힌트처럼 보상형 광고 자리 `IAdService.ShowRewarded`를 거침, 2026-10-17 — 지나간 판은 다시 하지 않음: 묶음을 다 돌면 처음부터). 그림 보상 없음.
* **보드 연출**(Phase 7.4) = `BoardView.PlayStroke` · `PlayClear` · `PlayShake`(값은 `MotionSettings`) — 세션 상태는 즉시 바뀌고 화면만 늦게 따라간다(경로는 Core `Trace`). `Render`가 진행 중인 연출을 끝난 모습으로 정리한다.
* **입력 잠금**(2026-10-08 · 10-05): `PuzzleController`는 클리어 또는 막힘이면 보드 입력(끌기 · 탭 · 방향 버튼 · 키보드)을 받지 않는다 — 되돌리기 · 처음부터 · 막힘 띠 되돌리기 · 힌트는 그대로. 보드를 덮는 패널(`_overlays` — 옵션 · 기록)이 열려 있으면 키보드를 무시하고, 되돌리기 · 처음부터는 끄는 중인 획을 취소한다(`BoardView.CancelDrag`).
* **챕터 그림**(Phase 5) = `ChapterArt`(선화 + 단계 조각, 단계 i ↔ 목록의 i번째 스테이지) · `ChapterView`(선택 화면 위 작은 그림 · `ChapterScreen` 큰 그림): 처음 클리어하면 클리어 띠가 뜰 때(`PuzzleController.ClearShown`) 그림 카드(`ClearBanner/PaintCard` — 그림 · "색칠 n / m", 켤 때와 되돌린 뒤 다시 풀어 띠가 다시 뜰 때 보드 영역 가운데로 옮김)에서 그 단계를 확대해 칠한 뒤 전체로 물러나고(`ChapterView._focusZoom` — 카드 그림만, 그림 크기와 같은 `PictureMask`의 RectMask2D 안. 테두리는 그림 밖 카드의 `Frame`이라 확대되지 않음), 띠 "다음"은 바로 다음 스테이지로 간다(B안 채택, 2026-11-13 사용자 — `DECISIONS.md`). 챕터를 완성한 클리어만 카드 없이 "다음" → 그림 화면(`ChapterScreen`)에서 "그림 완성!". 띠가 뜨기 전에 목록 버튼으로 나가면 목록의 작은 그림에서 칠한다. 다시 클리어하면 칠하지 않는다(`PuzzleController.FirstClear`). 카드는 띠의 자식이라 띠와 함께 켜지고 꺼지며, 스테이지 · 레슨 · 무한 모드를 열 때 `GameFlow`가 끈다. 그림을 바꿀 땐 (완성 그림 한 장이면 `ArtSplit.py` →) `ChapterArtExport.py` → `ChapterArtBuilder`를 차례로 실행한다(`AgentScripts/README.md`). 단계 조각 파일 이름이 같으면 `.meta` GUID가 유지되고 `ChapterArt`의 조각 위치만 바뀐다 — 첫 클리어 카드의 확대 배율은 조각 크기에서 나오므로 그림을 바꾸면 달라진다.
* **화면 디자인 기준**(Phase 7.1, 시안 A "종이와 갈색 선") = `UiTheme`(`Assets/Data/Settings/UiTheme.asset` — 바탕 · 글자/선 갈색 · 버튼 바탕 등. 퍼즐 칸 색은 팔레트라 여기 없음): `BoardSceneBuilder`가 이 값으로 씬 · 프리팹을 만든다(값을 바꾸면 BuildPrefabs → BuildScene). 버튼 모양 = 9-slice 둥근 사각형 `RoundFill` · `RoundRing` · 그림 테두리 `FrameRing` · 스테이지 버튼 외곽선 `HexLine`(`SpriteBuilder.BuildRound`).

## 4. 스테이지 데이터 · 저장 형식

* 프로토타입 포맷 `{"name": ..., "cells": [[q, r, 시작 색, 목표 색], ...]}` (GDD §3) + 선택 필드 `palette`(팔레트 이름, 없으면 기본 팔레트) · `minMoves`(최소 수, 솔버가 채움, 없으면 미표시). 로직은 `palette`를 이름(문자열)으로만 들고, 팔레트 에셋을 고르는 일은 표현 계층이 한다. 프로토타입에 들어 있는 스테이지 9개(포도 포함)는 이 포맷 그대로 옮겨 쓸 수 있다. 읽기는 `Stage.Parse` — Core 전용 파서다(`JsonUtility`는 UnityEngine이고 중첩 배열을 못 읽음, 2026-09-28 사용자 결정). `name` · `cells` 필수, 모르는 키 · 0~7 밖의 색 · 좌표 중복은 `FormatException`.
* **저장 형식 (2026-09-29 사용자 결정)**: 스테이지 = `Assets/Data/Chapters/ChapterN/Stages/<영문 이름>.json` TextAsset(이 포맷 그대로 — 프로토타입 코드와 복사 · 붙여넣기로 오감, git 차이가 읽힘). `minMoves`는 레벨 에디터가 저장할 때 솔버로 채운다. 순서 민감도는 저장하지 않고 에디터에만 표시. 게임이 여는 스테이지 목록은 `StageCatalog`(ScriptableObject, JSON TextAsset 순서 목록 — Phase 4 스테이지 선택 화면도 이것을 쓴다). 챕터는 `Chapter` 에셋(제목 · 부제 · 목록 · 그림, 2026-10-07)이 묶고 `GameFlow._chapters`(차례 — 앞 챕터 그림을 완성하면 다음 챕터, 2026-10-11)가 연다 — 파일 이름은 진행 기록의 키라 챕터 · 따라 하기 · 시험 목록 모두에서 겹치면 안 된다(`ContentRegressionTests`).

## 5. 저장 · 플랫폼 서비스

* 저장은 `PlayerPrefs`를 직접 부르지 않고 인터페이스 뒤에 둔다(앱인토스에서 네이티브 저장소로 교체). 광고는 인터페이스 자리만. 사운드 켜고 끄기와 백그라운드 전환 시 정지는 처음부터 구조에 넣는다. 효과음은 `SoundController`(클립 · 버튼 OnClick 배선은 `BoardSceneBuilder`, 획 소리 규칙은 `DECISIONS.md` 2026-11-08). 구현(2026-09-30): `IKeyValueStore` · `PlayerPrefsStore`(쓸 때마다 `PlayerPrefs.Save()` — WebGL은 그래야 IndexedDB에 남음), 키 `ColoringBoot.Progress`(클리어 · 최고 기록, Core `Progress`) · `ColoringBoot.PlayStats`(플레이테스트 기록, Core `PlayStats`) — 저장 형식은 머리줄(`progress 1` · `stats 2` — 2026-10-07 힌트 칸, `stats 1`도 읽음) + 탭 구분 줄, 깨지면 빈 기록으로 시작. 따라 하기를 봤는지는 `ColoringBoot.Tutorial`, 무한 모드 진행은 `ColoringBoot.Endless`(`endless 1`, 2026-10-07) — `?reset`이면 함께 지움. 스테이지는 파일 이름으로 구분. 광고는 `IAdService` · `NoAdService`. 주소 쿼리(테스트 주소 — GitHub Pages · localhost · 127.0.0.1 — 에서만, `UrlQuery.IsQaHost`, 2026-10-07): `?stage=<파일 이름>` · `?stats`(기록 패널 — 지금 목록 + 따라 하기) · `?reset`(진행 · 기록 지우기) · `?palette=<이름>`(모든 스테이지를 그 팔레트로 — 색 확인용) · `?lab`(시험 목록 11개 — 소재 맵 시험 · 챕터 1에서 빠진 옛 판, 모두 열림 · 그림 화면 없음, 2026-10-06 · 10-11 · 기믹 판은 10-12에 뺌) · `?chapters`(임시 챕터 `GameFlow._testChapters`를 뒤에 붙임 — 여러 챕터 흐름 확인, 2026-10-11).
* **안전영역**(2026-11-11): 모든 화면 · 패널은 `Canvas/SafeArea` 아래에 있고, `SafeAreaFitter`가 화면 크기 · `Screen.safeArea`가 바뀌거나(매 프레임 확인) WebGL에서 토스 인셋 번호가 바뀌거나 지난 토스 값 읽기가 실패했을 때(0.5초마다 확인) 이 패널의 앵커를 맞춘다. WebGL 빌드(`#if UNITY_WEBGL && !UNITY_EDITOR`)만 자체 jslib `Assets/Plugins/WebGL/ColoringBootSafeArea.jslib`으로 앱인토스 `window.AppsInToss.SafeAreaInsets.get()`(CSS px)과 캔버스 CSS 크기(`Module.canvas`)를 읽어 `Screen.safeArea`와 겹치는 영역(축마다 더 안쪽)을 쓴다 — 위는 `top + 10 + 44 + 8`(토스 `⋯ ✕`의 공식 위치 Android 10 · 높이는 공식 값이 없어 캡처 추정 약 34에 여유), 아래 · 왼쪽 · 오른쪽은 인셋 그대로(기기 노치 · 홈 표시줄의 `Screen.safeArea`가 더 안쪽이면 그쪽 — 2026-11-11 리뷰: Android 토스 인셋은 아래 0). 인셋과 캔버스 크기가 모두 CSS px라 배율을 쓰지 않는다(전제: 캔버스가 뷰포트를 덮음 — `AITTemplate`, 실기 확인). jslib은 브리지가 처음 보일 때 · 변경 구독이 성공할 때 · SDK `SafeAreaInsets.subscribe`의 `onEvent`마다 번호를 올리고(`CbSafeAreaVersion` — 구독이 실패했으면 부를 때마다 다시 시도), `SafeAreaFitter`는 0.5초마다 그 번호를 보고(토스 밖 WebGL의 JS 호출을 줄임) 번호 · 화면 크기 · `Screen.safeArea` 중 하나가 바뀌거나 지난 읽기가 실패했으면 `CbSafeAreaRead`로 여섯 값을 한 번에 읽는다(여섯 값을 모두 검사한 뒤에만 씀)(2026-11-11 보강 — 브리지가 늦게 생기거나 인셋만 바뀌어도 다시 맞춤). 토스 값을 못 쓰면 `Screen.safeArea` 배치 그대로 두고 종류별로 로드당 1회 로그 — `window.AppsInToss`가 없으면 정보(토스 밖 · Pages), 있는데 못 읽으면 에러(0.5초마다 다시 읽음), 구독이 아직 안 됐으면 경고(값은 적용 · 구독은 다시 시도), 여백을 뺀 패널이 캔버스의 절반보다 작으면 경고. SDK C# API는 쓰지 않는다(`DECISIONS.md` 2026-11-11). SDK를 올리면 브리지 이름이 바뀌었는지 샌드박스 실기로 다시 본다. 목록 화면은 `SelectScreen/Body`(위 -210 ~ 아래 265, `VerticalLayoutGroup`)가 작은 그림 칸(`PictureSlot` — ◀ ▶ 포함, 그림은 `AspectRatioFitter`로 4:5)과 격자(`Grid`)를 쌓는다: 격자는 줄 수만큼, 그림은 남는 높이만큼(최대 480×600). 패널이 짧거나 줄이 늘면 그림만 작아지고(그림 칸은 ◀ ▶ 높이 140 밑으로 줄지 않는다 — 화살표가 격자 · 부제와 겹치지 않게. 그만큼도 안 남으면 격자가 아래로 밀린다: 3줄이면 패널 높이가 1920의 약 72% 미만일 때) 격자는 잠김 안내 띠(아래 145~255) · [무한 모드](25~135)와 겹치지 않는다. 1920 높이 패널에서는 그림 위 -210 · 격자 위 -850(이전 고정 배치와 같음). 실측(에디터 1080×1920): 위 14% 줄임 → 그림 331×414, 4줄이면 1920 패널 350×437 · 14% 줄임 135×168.

## 6. WebGL 설정

* WebGL Build Support 설치 · 활성 빌드 타깃 WebGL 확인(`list_build_targets` · `get_build_settings`). WebGL은 품질 레벨 `Mobile`(→ `Mobile_RPAsset`, URP)을 쓴다. 적용된 설정: 압축 Brotli + Decompression Fallback · Managed Stripping High · IL2CPP OptimizeSize · 기본 캔버스 540×960 · 데이터 캐싱 · 스레드 끔 · 스플래시 끔(Phase 4.1) · 전용 템플릿 `PROJECT:ColoringBoot` · 제품 이름 "컬러링붓" · Name Files As Hashes(Phase 7.6, `AgentScripts/Setup/Phase7WebTemplate.cs`). 텍스처 압축: 챕터 그림만 ASTC(선화 4×4 · 색칠 단계 6×6, `ChapterArtBuilder`), UI 스프라이트는 압축하지 않음(2026-10-11 사용자 결정 — 휴대폰이 그대로 써 메모리가 줄고, PC 브라우저는 불러올 때 푼다).
* 설정 이유: GitHub Pages는 `Content-Encoding: br` 헤더를 주지 못해 Brotli 파일이 그대로는 로드에 실패한다 → Decompression Fallback. 빌드 파일 이름이 매번 같으면 브라우저가 GitHub Pages 캐시(10분)의 옛 파일과 새 파일을 섞어 `RangeError: Maximum call stack size exceeded`로 멈춘다(2026-10-03) → Name Files As Hashes · 템플릿 CSS는 `index.html` 안에.
* WebGL 전용 코드는 안전영역 하나(§5 — `SafeAreaFitter`의 `#if UNITY_WEBGL && !UNITY_EDITOR` · jslib 1개). Android APK와 에디터에는 들어가지 않는다.
* 빌드 크기 · 첫 로딩 · 배포 이력은 `Docs/BuildHistory.md`.

* **빌드**(2026-11-10): 활성 타깃을 오간다 — `switch_build_target` Android → `unity command build --target Android --outputPath Builds/Android/ColoringBoot.apk --confirm true` → 끝나면 WebGL로 되돌린다. 빌드 프로필 없음. 시험 APK는 Unity 디버그 키, 출시 키는 `Docs/Task.md` 9.3. 전환 중에는 `AIT` 메뉴 빌드를 쓰지 않는다(SDK 전환 대화상자가 에디터를 멈춘다).
* **설정**: 패키지 `com.jhseawater.coloringboot`(Android만) · 회사 `JHSeawater` · 세로 고정(회사 · 방향은 WebGL과 공용, `AgentScripts/Setup/Phase9AndroidSettings.cs`) · IL2CPP · ARM64만 · 최소 API 26 · 타깃 API 자동(실측 36) · GameActivity · 전체 화면(탐색 바가 게임 중 가려짐) · `enableOnBackInvokedCallback=true`. 챕터 그림은 WebGL과 같은 ASTC(선화 4×4 · 색칠 6×6, `ChapterArtBuilder`).
* **코드 분기는 두 곳뿐**(`GameFlow`의 `#if UNITY_ANDROID`): 시스템 뒤로가기(`LateUpdate`가 `Keyboard.escapeKey`를 읽어 `HandleBack` — `PuzzleController.Update`의 Esc 뒤에 돌아 옵션을 닫을 때 보드 선택이 풀리지 않는다, WebGL의 Esc에는 영향 없음)와 `Application.targetFrameRate = 60`. `HandleBack`: 옵션 닫기 → 보드(목록 버튼과 같음 — 단 따라 하기 중이면 `TutorialSeen`을 저장하지 않는다) → 그림 화면(목록) → 무한 난이도(뒤로 버튼과 같음) → 목록(타이틀) → 타이틀(앱 종료).
