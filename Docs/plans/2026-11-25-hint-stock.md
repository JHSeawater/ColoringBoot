# 힌트 개수 제한 (최대 3개 · 30분 충전) · 건너뛰기는 힌트 1개

## 원래 요청(그대로)
> 근데 지금 힌트 조건은 3개를 한도로 일정 시간마다 자동으로 하나씩 채워지고, 광고를 보면 3개 한도가 다시 채워지는 형식을 고려 중인데, 그럼에도 건너뛰기를 살리는게 구조적으로 옳은 것인가?

> 추천대로 하자. 출시 전에 넣고 시간마다 채우기로. 막다른 길 알림은 힌트 소모가 안되는 걸로 하고, 힌트를 써도 완벽으로 되도록. 그리고 만약에 힌트를 전부 썼을 때, 막다른 길에서 힌트를 사용하면 어떻게 될지도 생각해야 할 듯.

> 힌트가 0개 일때 막다른 길에서도 힌트가 차야 되도록 하고, 힌트가 하나라도 남아 있을 때만 사용하면 막다른 길임을 표시하는 대신 힌트 소모하는 하지 않는 쪽으로 하는건 어떤거 같음?

> 그대로 정하고, 나머지는 추천대로. 충전 간격은 30분

> 승인한다. 그대로 진행하라 (GDD §5 · §6 · §14 문구 승인)

## 목표
원스토어 출시 전에 힌트를 무제한에서 "최대 3개 · 30분마다 1개"로 바꾼다. 스케치북 건너뛰기는 광고 자리 대신 힌트 1개를 쓴다. 정본: GDD §5(스케치북) · §6(힌트) · `DECISIONS.md` 2026-11-25 "힌트는 한도 3개 …".

## 요구사항
1. 힌트는 최대 3개다. 3개보다 적으면 30분마다 1개씩 찬다. 앱이 꺼져 있던 시간도 친다(저장한 시각으로 계산).
2. 처음 실행(저장 값 없음)은 3개로 시작한다.
3. 챕터 · 스케치북 · 시험 목록이 같은 힌트를 쓴다.
4. 힌트가 1개 이상일 때 누르면 탐색한다.
   - 결과가 다음 한 수(`HintKind.Next`)면 1개를 쓰고 보여 준다.
   - 막다른 길(`Undo`) · 못 찾음(`Unknown`)이면 쓰지 않는다.
   - 결과가 나온 뒤에만 쓴다. 탐색 중 판을 떠나면 그대로다.
   - 판 상태가 그대로인데 다시 누르면 이미 보여 준 다음 한 수를 쓰지 않고 다시 보인다(검수 지적 3 — 사용자 "전부 추천대로", 2026-11-25).
5. 힌트가 0개일 때 누르면 탐색하지 않고 다음 힌트까지 남은 시간을 안내한다. 막다른 길도 알려 주지 않는다.
6. 혼자 풀기 레슨(`TutorialLessons.IsFree`)에서는 힌트를 쓰지 않는다. 0개여도 탐색한다.
7. 힌트 버튼에 남은 개수를 보인다. 0개면 남은 시간을 보인다. 앱이 켜져 있는 동안 차면 바로 갱신한다.
8. 스케치북 건너뛰기:
   - 안 풀린 판이고 1개 이상이면 확인 창을 띄운다. [건너뛰기]를 누르면 힌트 1개를 쓰고 넘긴다. [취소] · Android 뒤로가기는 아무것도 바꾸지 않고 닫는다.
   - 0개면 창 없이 넘기지 않고 5와 같은 안내를 한다.
   - 풀린 판이면 지금처럼 힌트 없이 넘긴다.
   - 건너뛰기에서 광고 자리(`IAdService.ShowRewarded`)를 뺀다.
9. 힌트를 써도 최소 수면 "완벽"이다(지금과 같음 — 바꿀 것 없음).
10. 광고로 다시 채우기는 광고가 있는 플랫폼에서만 보인다. 지금은 광고 플랫폼이 없으므로(원스토어 판 광고 없음 · 앱인토스 연동 전) **이번 작업에서는 화면을 만들지 않는다.** Core에 "한도까지 채우기"만 두고, 연결은 9.4 광고 연동에서 한다(아래 정한 것 2).
11. `?reset`이면 힌트도 처음 상태(3개)로 돌아간다.

## 실행 방식
Full Plan이 맞다. 새 저장 기록(키 · 머리줄)이 생기고, 힌트 · 건너뛰기 흐름과 광고 진입점이 바뀐다(CLAUDE.md §2 — 저장 형식 · 광고 연동). 붓질 · 판정 · 솔버는 바꾸지 않는다.

## 설계

### Core — `HintStock` (새 파일 `Assets/Scripts/Core/Records/HintStock.cs`)
- 순수 C#이고 시각은 인자로 받는다(`long nowSeconds` — 유닉스 초). 시계는 Core가 아니라 표현 계층이 읽는다. 이렇게 해야 테스트에서 시간을 마음대로 준다.
- 상수:
  - `Max = 3`
  - `ChargeSeconds = 1800`
  - 게임 규칙 값이라 Core 상수로 둔다. Core는 ScriptableObject를 쓸 수 없다.
- 상태:
  - `count`(0~3)
  - `anchor`: 충전 시계가 시작된 시각(유닉스 초). `count == Max`일 때는 쓰지 않는다.
- 메서드:
  - `Count(now)`: 지난 시간만큼 채운 뒤 개수를 돌려준다.
    - 채우는 수 `n = (now - anchor) / ChargeSeconds`
    - `count = min(Max, count + n)`
    - 덜 찼으면 `anchor += n * ChargeSeconds`
  - `SecondsToNext(now)`: 다음 1개까지 남은 초. 가득이면 0.
  - `TrySpend(now)`: 채운 뒤 1개 이상이면 1개를 쓰고 true.
    - 가득에서 쓰면 `anchor = now`로 시계를 시작한다.
  - `Fill()`: 한도까지 채운다(9.4 광고 보상용).
  - `Serialize()`, `Deserialize(text, out RecordReadStatus)`: 머리줄 `hints 1`, 줄 하나 `count \t anchor`. 공용 뼈대 `RecordHeader.Read`를 쓴다.
- 시계가 뒤로 간 경우(`now < anchor`): `anchor = now`로 맞춘다. 늘어나지 않는다.
  - 바로잡은 값은 저장하지 않는다(저장은 쓸 때 · 채울 때만). 그래서 기기 시계가 저장된 시각보다 계속 뒤에 있으면, 앱을 켤 때마다 충전 시계가 처음부터 다시 시작한다. 시계가 저장된 시각을 지나거나 힌트를 한 번 쓰면(그때 저장) 정상으로 돌아온다. 드문 경우라 받아들인다(검수 지적 4).
- 시계를 앞으로 돌려 빨리 채우는 것은 막지 않는다. 광고가 없는 판에서는 영향이 작다(`DECISIONS.md` 2026-11-25 대화 — 아래 정한 것 4).
- 읽기 실패:
  - 깨짐 · 범위 밖(count < 0 · > Max · anchor < 0): 그 줄을 버리고(`LinesDropped`) 기본값 3개로 시작한다.
  - 새 버전: 기존 세 기록과 같은 규칙(`SaveData.Read`)을 따른다.
- 줄이 여러 개면 마지막 줄이 이긴다(기존 기록과 같은 규칙).

### 저장 — `SaveData`
- 키는 `ColoringBoot.Hints`이고 `RecordKeys`에 넣는다(읽기 상태 · `.Unread` 백업 · `?reset` 대상).
- `Hints` 속성과 `SaveHints()`를 둔다.
- 저장 시점: 쓸 때 · 채울 때(`Fill`)만. 시간 충전은 저장한 (count, anchor)에서 다시 계산되므로 저장하지 않는다.
  - 붓질마다 쓰지 않는다. 9.4 저장소 교체 준비의 "쓰기 줄이기"와 맞다.
- 이미 있는 기록(`progress 1` · `stats 2` · `endless 1`)의 형식은 바꾸지 않는다. 새 키만 하나 생긴다.

### 표현 — `PuzzleController`
- 시각은 `DateTimeOffset.UtcNow.ToUnixTimeSeconds()` 한 곳(`private static long Now()`)에서 읽는다.
- `RequestHint()`:
  - 레슨(혼자 풀기)이면 지금처럼 탐색한다(쓰지 않음).
  - 이미 값을 치른 다음 한 수(`_paidHint`)가 있으면 탐색 · 소모 · `PlayStats.Hinted` 없이 그 수를 다시 보인다(개수와 상관없이 — 0개여도).
  - 아니면 `Count(now) == 0`일 때 탐색 없이 안내 띠에 남은 시간 문구를 띄우고 끝낸다.
  - 1개 이상이면 탐색한다(`ShowHint`).
  - `_ads.ShowRewarded`를 거치지 않는다.
- `FinishHint`:
  - `Next`면 레슨이 아닐 때 `TrySpend(now)` → `SaveHints()` 뒤 손가락을 보인다.
  - `TrySpend`가 false면(탐색 중 다른 곳에서 마지막 1개를 쓴 경우 — 지금 흐름에는 없지만 방어) 수를 보이지 않고 남은 시간 안내를 띄운다.
  - `Undo` · `Unknown`은 지금처럼 보이고 쓰지 않는다.
- 다시 보기(`_paidHint`, 검수 지적 3):
  - `Next`로 1개를 쓰면 그 `Hint`를 `_paidHint`에 둔다(레슨이면 두지 않는다 — 어차피 무료).
  - 판 상태가 바뀌는 곳에서 지운다: 받아들인 붓질(`OnBrushRequested`에서 `Brush`가 true) · `Undo` · `Restart` · `Open`. 되돌렸다가 같은 상태로 돌아와도 지운 채로 둔다(보수적으로 — 같은 상태인지 비교하지 않는다).
  - 다시 보일 때는 `FinishHint`의 `Next` 표시 부분(손가락 · "남은 N수" 띠)을 같이 쓴다. 표시 코드를 두 벌로 만들지 않는다.
  - 버튼 글자는 남은 개수 그대로다(다시 보기가 무료라고 따로 알리지 않는다).
- `PlayStats.Hinted`(힌트를 본 횟수)는 탐색을 시작할 때 센다(지금과 같음). 0개라 탐색하지 않은 누름은 세지 않는다.
- 버튼 글자: 지금 `BottomButton`의 글자를 `_hintLabel`(TMP)로 받는다.
  - 1개 이상: `힌트 2`
  - 0개: `힌트 · 12분`
  - 레슨: `힌트`
- 갱신(`Update`):
  - 매 프레임에 `long` 비교만 한다. 다음 충전 시각이나 표시 분이 바뀌는 시각이 지났을 때만 글자를 다시 쓴다.
  - 그래서 문자열은 분당 한 번 이하로 만든다. 매 프레임 할당 금지(`.claude/rules/game-code.md`).
  - 보드 화면이 꺼져 있으면 갱신할 필요가 없다. 판을 열 때 `Refresh`에서 한 번 맞춘다.
- `_hintButton.interactable`은 0개여도 켠다. 눌러야 안내가 나온다. 탐색 중 · 클리어 · 따라 하기 잠금은 지금과 같다.
- 건너뛰기용 공개 메서드 두 개 — 힌트 판단을 `PuzzleController` 한 곳에 둔다:
  - `int HintsForSkip()`: 지금 개수(채운 뒤). 0이면 남은 시간 안내 띠를 띄운다.
    - 1개 이상이면 진행 중인 힌트 탐색을 버린다(`StopHintSearch` → `Refresh`, 쓰지 않음). 탐색 코루틴은 확인 창이 떠 있어도 계속 돌아, 버리지 않으면 창이 떠 있는 동안 `Next`로 끝나 1개를 쓰고 [건너뛰기]로 1개를 더 쓴다(검수 지적 1). 버린 탐색의 `PlayStats.Hinted`는 이미 센 그대로 둔다(탐색 중 판을 떠난 경우와 같다).
  - `bool SpendHintForSkip()`: 1개를 쓰고 저장한다. 실패하면 false와 안내(방어 — 위에서 탐색을 버려 창이 떠 있는 동안 개수가 줄 길은 없다).
- `SetAds` · `_ads` 필드는 힌트가 더는 광고를 부르지 않으므로 지운다. `IAdService.ShowRewarded`는 9.4 "광고로 채우기"가 쓸 자리라 인터페이스에 남기고 주석을 고친다.

### 표현 — `GameFlow.SkipEndless`
- 풀린 판: 지금과 같다(푼 것으로 다음 판).
- 안 풀린 판:
  - `_puzzle.HintsForSkip()`이 0이면 끝(안내는 PuzzleController가 띄움).
  - 1개 이상이면 확인 창(`SkipConfirmView`)을 남은 개수와 함께 연다.
  - [건너뛰기] → 창을 먼저 닫는다. 그사이 판이 풀렸으면(`_puzzle.IsSolved` — 방어, 지적 2) 힌트 없이 풀린 판 길로 간다. 아니면 `_puzzle.SpendHintForSkip()`이 true일 때 `Endless.Skip` → `SaveEndless` → `OpenEndless`.
  - [취소] → 창만 닫는다.

### 표현 — 건너뛰기 확인 창 (새 파일 `Assets/Scripts/Game/Screens/SkipConfirmView.cs`)
- 옵션 창(`OptionsView`)과 같은 방식: 보드 화면을 덮는 패널, 씬 빌더(`BoardSceneBuilder`)가 만든다. 화면 디자인 값은 `UiTheme`에서 읽는다(옵션 창과 같은 색 · 글꼴).
- 내용: `힌트 1개를 써서 이 판을 건너뛸까요?` · `남은 힌트 {개수}개` · [건너뛰기] [취소]. 개수는 창을 열 때 한 번 쓴다.
- `Show(int hints)` · `Hide()` · 이벤트 `Confirmed`(GameFlow가 구독 — `OnEnable` 구독 · `OnDisable` 해제 규칙).
- 창이 떠 있는 동안 보드 입력은 덮개 패널이 받아 막는다(옵션 창과 같음). 패널 바깥(빈 곳) 터치는 닫지 않는다 — 실수로 닫히는 것보다 명시적인 [취소]가 낫다.
- 키보드: 덮개 패널은 포인터만 막는다. 빌더가 창을 `PuzzleController._overlays`에 넣는다(옵션 · 기록 패널과 같이, `BoardSceneBuilder.cs` `SetArray(controller, "_overlays", …)`). 그래야 PC에서 숫자키 · Ctrl+Z가 뒤의 보드를 움직이지 않고 걸린 시간도 쌓이지 않는다(검수 지적 2).
- Android 뒤로가기(`GameFlow.HandleBack`): 옵션 창 다음, 보드보다 먼저 — 창이 떠 있으면 창만 닫는다(=취소).
- 보드를 떠나는 모든 길(목록 · 뒤로가기 · 옵션의 규칙 다시 보기)에서 창이 남지 않게 판을 열거나 보드를 끌 때 `Hide`.
- `_ads.ShowRewarded` 호출을 뺀다. 그러면 건너뛰기는 광고 콜백이 늦게 와도 문제없다 — Task 9.4 M6의 대상에서 빠지고 `Next` · `ContinueAfterPicture`만 남는다.
- 탐색 중 건너뛰기: 막지 않는다. 창을 열 때(`HintsForSkip`) 탐색을 버리므로 힌트는 건너뛰기에서만 1개 쓰인다. [취소]를 누르면 탐색 결과 없이 판으로 돌아온다(다시 누르면 새로 탐색).

### 문구 (새 화면 문구 → 폰트 다시 만들기)
- 남은 시간 안내: `힌트가 없어요 · 다음 힌트까지 {분}분`
  - 분은 올림 — 1초 남아도 1분, 그래서 0분은 나오지 않는다.
- 버튼: `힌트 {개수}` · `힌트 · {분}분`
- 확인 창: `힌트 1개를 써서 이 판을 건너뛸까요?` · `남은 힌트 {개수}개` · `건너뛰기` · `취소`
- 숫자와 "힌트"는 이미 있는 글자다. 새로 늘 글자는 "없 · 어 · 요 · 까 · 지 · 분 · 써 · 서 · 뛸 · 남 · 은 · 취 · 소" 등 아틀라스에 없는 것만 늘어난다. 장 수가 바뀌는지 `FontBuilder.Preview`로 먼저 본다.

## 위험
- **회귀:** 붓질 · 판정 · 솔버 · 스테이지는 바꾸지 않는다. 포도 · 프로토타입 · 콘텐츠 회귀 테스트는 영향이 없어야 하고, 전체 실행으로 확인한다. `HintSearch` · `PuzzleSession.StartHint`는 그대로다.
- **저장 호환:**
  - 새 키 하나만 생기고, 옛 저장(키 없음)은 3개로 시작한다.
  - 기존 세 기록의 머리줄은 바뀌지 않는다.
  - 캐시된 옛 빌드는 새 키를 모르고 무시한다(해 없음).
  - 앱인토스 저장소 교체(9.4) 때 이 키도 같이 옮겨야 한다 — Task 9.4 저장소 항목에 적는다.
- **읽기 실패가 3개로 시작하는 것:** 깨진 값이면 힌트를 더 받는다. 손해 방향이 플레이어 쪽이라 받아들인다. 원본은 `.Unread`에 남는다.
- **시계:**
  - `DateTimeOffset.UtcNow`는 WebGL에서 브라우저 시계를 쓴다.
  - 시계를 앞으로 돌리면 빨리 찬다. 막지 않는다 — 서버 시각이 없다.
  - 뒤로 돌리면 늘지 않는다. 저장된 시각보다 계속 뒤면 켤 때마다 충전 시계가 다시 시작한다(설계 `HintStock` — 받아들임).
- **프레임 비용 · 할당:** `Update`는 `long` 비교만 한다. 글자 갱신은 분당 한 번 이하.
- **빌드 용량:** 코드 몇 KB와 폰트 글자 몇 개. 아틀라스 장 수가 늘면 보고한다.
- **WebGL 제약:** 스레드 · 파일 시스템을 쓰지 않는다. 탐색은 지금처럼 프레임에 나눠 돈다.
- **확인 창 잔류:** 창이 열린 채 보드를 떠나면 다음 판 위에 남을 수 있다 — 판을 열 때 · 보드를 끌 때 `Hide`(4단계 완료 기준에 넣음). 창의 [건너뛰기]는 한 번만 처리한다(누르면 먼저 창을 닫고 진행 — 두 번 눌러 2개 쓰지 않게).
- **창 뒤에서 도는 탐색 · 키보드(검수 지적 1 · 2):** 창을 열 때 탐색을 버리고, 창을 `_overlays`에 넣는다. [건너뛰기]는 `IsSolved`를 다시 본다.
- **다시 보기의 범위(검수 지적 3):** 같은 판 상태에서만 무료이고, 붓질 · 되돌리기 · 처음부터 · 판 열기에서 지운다. 무료로 얻는 것은 이미 값을 치른 같은 수뿐이다.
- **플레이 기록 의미:** `PlayStats` 힌트 수는 "탐색을 시작한 횟수"로 지금과 같다. 0개 누름 · 같은 수 다시 보기는 세지 않는다 — DevelopLog에 적는다.
