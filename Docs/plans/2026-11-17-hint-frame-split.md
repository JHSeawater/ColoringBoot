## 지금 구조(확인한 것)

- `Solver.Solve`(`Assets/Scripts/Core/Solver/Solver.cs`)는 너비 우선 탐색을 한 번에 끝까지 돈다. 부르는 곳: `PuzzleSession.FindHint` · `Generator` · `SeedSearch` · `LevelEditorController` · `AgentScripts`의 도구(`ChapterSurvey` · `SubjectLab` · `Phase8Chapters` 등) · 테스트.
- `PuzzleSession.FindHint(limit)`는 지금 상태를 풀어 보고, 못 풀면 기록을 최근 것부터 거슬러 올라가며 풀릴 때까지 `Solve`를 다시 부른다(상한은 상태 하나당).
- `PuzzleController.ShowHint`가 `FindHint(HintLimit = 200000)`를 한 프레임에 부른다. 무한 모드 · 혼자 풀기 레슨도 같은 `PuzzleController`를 쓴다.
- 힌트 버튼은 `IAdService.ShowRewarded(ShowHint)`를 거친다(지금은 바로 실행).
- `PuzzleController`는 씬 루트의 `Puzzle` 오브젝트에 붙어 있다(`BoardSceneBuilder.cs` 311줄 · `Board.unity`에서 부모 없음 — 검수 때 확인). `BoardScreen`을 꺼도 `PuzzleController`의 코루틴은 멈추지 않고 `OnDisable`도 불리지 않는다 → 탐색 코루틴은 `Close` · `Open`에서 직접 멈춘다(`StopAfterStroke`와 같은 방식).
- 보드를 떠나는 `GameFlow` 경로는 모두 `_puzzle.Close()`(`ShowSelect` · `ShowPicture` · `ShowEndless`) 또는 `_puzzle.Open`(`OpenStage` · `OpenLesson` · `OpenEndless`)을 거친다.
- 잠금 상태(보드 입력 · 되돌리기 · 처음부터 · 힌트 버튼)는 `Refresh`가 정한다 — 막힌 판은 보드 입력 잠금, 0수면 되돌리기 · 처음부터 흐림, 따라 하기 레슨은 힌트 버튼 흐림.

## 요구사항

1. 힌트 탐색은 프레임마다 정해진 시간만큼만 돌고 다음 프레임에 이어서 돈다(`CLAUDE.md` §6 — 스레드 금지 · 코루틴).
2. 힌트 결과는 지금과 같다: 같은 상태에서 같은 `Hint`(종류 · 획 · 수). 탐색 순서를 바꾸지 않는다.
3. `Solver.Solve`의 결과(풀이 경로 · `Explored` · `Limited` · `DeadAtStart`)는 모든 스테이지에서 지금과 같다 — 포도 · 프로토타입 · 콘텐츠 회귀 테스트 통과.
4. 탐색이 한 프레임에 끝나지 않으면 "찾는 중" 안내를 보이고, 끝나면 지금의 안내(손가락 표시 · 문구)로 바꾼다. 한 프레임에 끝나면 지금과 똑같이 보인다.
5. 탐색하는 동안 보드 상태가 바뀌지 않는다(붓질 · 되돌리기 · 처음부터 · 힌트 다시 누르기를 받지 않는다 — 물을 것 2). 탐색이 끝나면 잠금은 `Refresh` 기준 상태로 돌아간다 — 막힌 판의 보드 입력은 계속 잠겨 있다(`CLAUDE.md` §5).
6. 탐색 중 보드를 떠나면(목록 · 다른 스테이지 열기) 탐색을 버리고, 다시 들어왔을 때 입력이 잠겨 있지 않으며 버린 탐색의 결과가 나중에 뜨지 않는다.
7. 탐색 구현은 하나만 둔다 — 한 번에 도는 `Solve` · `FindHint`는 나눠 도는 탐색을 끝까지 돌리는 것으로 한다(같은 규칙이 두 곳에 있지 않게).
8. 솔버를 쓰는 도구 · 테스트가 눈에 띄게 느려지지 않는다(물을 것 4).

### 4. `PuzzleController` — 코루틴 · 잠금 · 안내
- 목표: 요구사항 1 · 4 · 5 · 6.
- 수정 대상: `PuzzleController.cs` · (필요하면) `BoardQa.cs` · 폰트 빌더 실행.
- 선행: 3.
- 내용:
  - `ShowHint`는 탐색을 시작해 첫 프레임 몫을 바로 돌린다. 끝났으면 지금처럼 결과를 보이고, 아니면 안내 띠에 "찾는 중" 문구를 띄우고 코루틴으로 프레임마다 이어 돈다. 프레임 몫은 시간으로 잰다(물을 것 3 — 일정 개수를 펼칠 때마다 시계를 본다).
  - 탐색 중에는 보드 입력 · 되돌리기 · 처음부터 · 힌트를 받지 않는다. 잠금은 두 겹이다 — 버튼을 흐리게 하고, `Undo` · `Restart` · `RequestHint` · `OnBrushRequested` 메서드 안에서도 막는다(Ctrl+Z는 `Undo()`를 바로 부르고, `onClick.Invoke`는 흐린 버튼도 누른다).
  - 탐색이 끝나면 잠금을 그냥 풀지 않고 `Refresh` 기준 상태로 되돌린 뒤 결과를 보인다(막힌 판은 보드 입력 잠금 유지 · 0수면 되돌리기 흐림 · 레슨의 힌트 버튼).
  - 탐색을 버리는 자리: `Close` · `Open(Stage …)`(다른 `Open` · `OpenLesson`은 이것을 거친다). 버릴 때 코루틴을 직접 멈추고(`StopCoroutine`) 필드를 비운다 — `BoardScreen`이 꺼져도 코루틴은 저절로 멈추지 않는다. 잠금은 뒤따르는 `Refresh`(`Open`)가 맞춘다.
  - 힌트 횟수 기록(`Stats.Hinted`)은 요청할 때 한 번 적는다(탐색을 시작하는 자리 — 버려진 탐색도 누른 횟수로 센다). `힌트 계산 N ms` 로그는 프레임 몫을 더한 값과 누른 때부터 결과까지의 시간 · 프레임 수를 함께 남긴다.
- 완료 기준: 컴파일 · EditMode 전체 · `QaScene` 통과. 에디터 플레이에서 호박 막다른 길 힌트 — ① 탐색 중 `Time.frameCount`가 계속 는다(로그의 프레임 수) ② "찾는 중" 안내가 보였다가 "지금은 풀 수 없어요 · 5수 되돌려 보세요"로 바뀐다 ③ 탐색 중 붓질 · 되돌리기 · 처음부터 · 힌트 다시 누르기가 먹지 않는다(버튼 흐림 + 메서드 직접 호출 둘 다) ④ 탐색 중 [목록]으로 나갔다가 같은 판을 다시 열면 입력이 되고, 탐색이 끝났을 시간(3초)이 지나도 옛 힌트 안내가 뜨지 않으며 힌트 횟수가 더 늘지 않는다 ⑤ 포도(금방 끝나는 판)에서는 "찾는 중"이 보이지 않고 지금과 같다 ⑥ 한글이 □로 나오지 않는다 ⑦ 막힌 판(막힘 띠가 뜬 상태)에서 힌트가 끝난 뒤에도 보드 입력은 잠겨 있고 되돌리기는 된다 ⑧ 0수 상태에서 힌트가 끝난 뒤 되돌리기 · 처음부터는 흐린 그대로다.
- 검증: 에디터 플레이(`BoardQa` · `capture_game_view`) · EditMode 테스트 · `QaScene`. 탐색 중 확인(③ · ④)은 힌트를 누른 같은 `run_script` 호출 안에서 한다 — 호출을 나누면 2~3초 창을 놓친다. `BoardQa.Undo`는 버튼이 흐리면 누르지 않고 돌아오므로, 메서드 안 잠금은 `onClick.Invoke`(`BoardQa.Press`)로 따로 본다.

## 위험

- 회귀(가장 큼): 탐색 순서가 바뀌면 같은 최소 수라도 다른 풀이가 나와 힌트 · 생성기 결과(무한 모드 묶음 재현) · 프로토타입 일치가 깨진다 → 1단계에서 옛 구현과 나란히 비교한 뒤에만 2단계로 간다. 테스트를 통과시키려고 기준을 바꾸지 않는다.
- 도구 성능: `Solve`는 `SubjectLab` · 생성기에서 수십만 번 불린다. 탐색 상태를 객체 필드로 옮기면 느려질 수 있다 → 0단계 기준선과 비교하고, 폭을 넘으면 멈추고 보고한다.
- 버린 탐색이 계속 도는 버그: `PuzzleController`는 씬 루트에 있어 보드 화면이 꺼져도 코루틴이 멈추지 않는다 → 버리는 자리에서 `StopCoroutine`을 빠뜨리면 옛 탐색이 끝난 뒤 새로 연 판에 옛 힌트를 띄운다. 4단계 완료 기준 ④로 확인한다.
- 잠금이 잘못 풀리는 버그: 탐색 뒤 보드 입력을 그냥 켜면 막힌 판에서 붓질이 된다(`CLAUDE.md` §5 위반) → `Refresh` 기준으로 되돌리고 4단계 완료 기준 ⑦ · ⑧로 확인한다.
- 총 시간: 프레임마다 프레임 몫만큼만 계산하므로 끝나는 시각이 늦어진다(멈춤이 없어지는 대신). 계산 추정(60 Hz · 그리기 시간 무시): 프레임 몫 8 ms면 한 프레임 16.7 ms의 48%라 약 2배(PC 1,287 ms → 약 2.7초), 25 ms면 두 프레임(33.3 ms)에 한 번 그려 약 1.3배(약 1.7초). 그동안 되돌리기 · 처음부터가 잠긴다. 휴대폰은 재지 않았다 — PC보다 느린 만큼 "찾는 중" 안내가 길게 보인다. 실제 값은 5단계에서 잰다.
- 안내 깜빡임(추정, 재지 않음): 첫 프레임 몫은 넘지만 금방 끝나는 판에서는 "찾는 중" 문구가 한두 프레임 보였다 바뀔 수 있다 — 4단계 에디터 플레이에서 눈에 띄면 보고한다.
- 저장 데이터: 바뀌지 않는다(머리줄 · 진행 기록 키 · 힌트 횟수 기록 방식 그대로).
- 빌드 용량: 코드만 조금 는다. 새 문구의 글자가 폰트에 없으면 글리프가 늘지만 아틀라스 장 수(2장)는 그대로일 것으로 본다 — 5단계에서 실측해 보고한다.
- WebGL 제약: 코루틴만 쓴다(스레드 · `System.IO` 없음). 탭이 뒤로 가면 프레임이 멈춰 탐색도 멈췄다가 돌아오면 이어진다.
- 하지 않는 것: 솔버의 메모리 할당 줄이기(획마다 배열 복사) · 되돌리기 안내의 재탐색 줄이기(이분 탐색) · 무거운 판 교체 — 이번 범위가 아니다(`DECISIONS.md` 2026-11-17).
