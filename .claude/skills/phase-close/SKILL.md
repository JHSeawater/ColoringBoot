# /phase-close — Phase 종료 절차

Task.md 상단 "문서 사용 규칙"의 완료 기준(DoD)을 기계적으로 집행한다.
인자: Phase 번호(예: `/phase-close 1`). 없으면 Task.md 헤더의 "현재 위치"에서 대상 Phase를 추론한다.

## 1. DoD 게이트 — 하나라도 걸리면 닫지 않고 보고 후 중단

1. **미완 항목**: 대상 Phase에 `[ ]` 항목이 남아 있으면 **닫을 수 없다.** 목록을 보여주고, 이월이 타당한 항목은 어느 Phase로 옮길지 사용자에게 묻는다.
2. **QA 존재**: `[x]` 항목 중 `[QA]` 태그가 최소 1개 있어야 한다.
3. **실측 근거**: 각 `[x]`는 "MCP 실측 · 테스트 통과 · 실플레이로 확인됨"이어야 한다. 항목 본문 · DevelopLog 어디에도 근거가 없는 항목은 의심 목록으로 보고한다 — 근거 없는 `[x]`가 "완료 표기와 실제 상태가 어긋나는" 사고의 가장 흔한 원인이다.
4. **테스트**: EditMode 테스트가 존재하면 `run_tests`(mode=editor) 전체를 실행해 모두 통과해야 한다. 실패가 있으면 닫지 않는다.
5. **완료 조건**: Phase 헤더의 "완료 조건"이 실제로 관측되었는지 확인한다. WebGL·실기에 관한 조건은 에디터가 아니라 WebGL 빌드(브라우저 · 휴대폰)에서 확인된 것이어야 한다.
6. **태그 규칙**: 태그 없는 항목이 없어야 한다.

## 2. 문서 갱신 (게이트 통과 시)

- **`Task.md`**: Phase 헤더에 `✅ (YYYY-MM-DD 완료)` 표기, 문서 상단 "현재 위치"를 다음 Phase로 갱신.
- **`DevelopLog.md`**: **최상단**에 추가 — 포맷: 날짜(YYYY-MM-DD) · 제목 · 작업 내용 · 해결된 이슈 (CLAUDE.md §2).
- **정합성 점검**:
  - 이 Phase에서 `GDD.md` §15 미정 사항이 확정됐거나, GDD와 다르게 구현한 부분이 있으면 GDD 반영안을 제시한다. GDD는 기획자(사용자) 문서이므로 **승인 후에만 수정**한다.
  - `CLAUDE.md`의 규칙 · 현황 서술(§3 게임 규칙, §4 WebGL 현황, §8 자주 하는 실수 등)이 낡았으면 정정안을 제시한다.
  - 정정 사실은 Task.md의 `[Doc]` 항목으로 남긴다.

## 3. 마무리

- 변경 파일 목록과 커밋 메시지를 제안하고 **사용자 승인 후** 커밋한다(예: `docs: close Phase N (<제목>)`). 에셋을 커밋할 때는 `.meta`가 함께 들어갔는지 확인한다.
- 다음 Phase 헤더의 **선행 조건**이 충족됐는지 확인해 한 줄로 알린다.
